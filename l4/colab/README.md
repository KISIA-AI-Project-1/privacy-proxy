# Colab에서 학습 돌리기

노트북: [klue_ner_train_colab.ipynb](klue_ner_train_colab.ipynb)

## 캐글과 다른 점

Colab은 **아무것도 자동으로 보존하지 않는다.** `/content/`는 세션이 끝나면
사라지므로 Drive를 마운트하고 거기에 직접 써야 한다. 노트북 2번 셀이 마운트와
쓰기 확인을 먼저 하고, 안 되면 학습 전에 멈춘다.

무료 Colab은 브라우저를 닫으면 세션이 끊긴다. 40~60분 동안 탭을 열어둬야 한다.
(캐글은 `Save & Run All` 로 꺼도 되지만 데이터셋 업로드 단계가 필요하다.)

## 순서

1. **런타임 → 런타임 유형 변경 → `T4 GPU`**
2. 노트북 업로드 (`파일` → `노트북 업로드`)
3. 코드 준비 — 둘 중 하나
   - Drive의 `MyDrive/privacy-proxy/code/l4` 에 `l4/` 폴더를 복사 (권장, 재업로드 불필요)
   - 또는 3번 셀에서 `l4_ner.zip` 업로드 (자동으로 Drive에 백업해둔다)

   ```bash
   zip -r l4_ner.zip l4 -x "l4/kaggle/*" -x "l4/colab/*" -x "*__pycache__*"
   ```
4. 위에서부터 순서대로 실행

산출물은 `MyDrive/privacy-proxy/l4-ner/` 에 쌓인다.

## 세션이 끊기면

**6번 셀을 다시 실행하면 된다.** 처음부터 돌지 않는다.

| 단계 | 방어 수단 |
| --- | --- |
| run 단위 | `metrics.json` 이 있는 run은 건너뛴다 |
| 스텝 단위 | `SAVE_STEPS` 마다 체크포인트를 남기고 거기서 이어간다 |

체크포인트 하나가 **1.3GB**다(모델 420MB + 옵티마이저 상태 840MB).
Drive 쓰기가 느려서 `SAVE_STEPS` 를 너무 작게 잡으면 학습보다 저장이 오래 걸린다.
기본값 500이면 T4에서 epoch당 2~3회다. run 하나가 15분쯤이라 사실상 run 단위
건너뛰기가 주된 방어선이고 스텝 체크포인트는 보조 수단이다.

`SAVE_TOTAL_LIMIT = 1` 로 최신 체크포인트 하나만 남긴다. Drive 무료 용량이
15GB라 이걸 안 묶으면 금방 찬다. 9번 셀이 학습 후 체크포인트를 지운다.

## 5번 셀을 꼭 확인할 것

학습 전에 평가 경로 자체를 검증한다. 정답을 그대로 통과시켜 상한 F1이 0.95
이상인지 보고 아니면 멈춘다. 로컬에서 잰 값은 **0.9816**이다.

여기서 0.73 근처가 나오면 엔티티 내부 공백 잇기가 깨진 것이고, 그 상태로
학습하면 모델이 아무리 좋아도 F1이 0.73을 넘지 못한다.

## 결과 해석

- **성공 기준 0.8은 상한 0.9816 대비로 읽는다.** 1.0이 아니다. 남은 1.8%는
  `'스타뎀의'` 가 한 서브워드라 `'스타뎀'` 만 떼어낼 수 없는 조사 경계 한계이고,
  다음 주 `alignment/` 가 회수할 몫이다.
- **`len256` run은 차이가 안 나오는 게 정상이다.** KLUE-NER 문장은 최대 145자라
  256에서도 512에서도 잘리지 않고, dynamic padding이라 연산량이 같다.
  "차이 없음"이 결과다.
- **지연시간은 GPU 값이다.** 로컬 CPU 실측은 90ms/건이었다. L4를 CPU로 서빙할지
  GPU로 할지에 따라 봐야 할 값이 다르다.
