# 0003. L5 nullable confidence와 tier 우선 중첩 해소

- 상태: Proposed (8b98395에 구현됨; 공통 계약 통합 리뷰 대기)
- 날짜: 2026-09-26
- 관련 레이어: L3, L4, L5, L6

## 배경

생산자의 confidence 미산정과 실제 0점은 의미가 다르다. 서로 다른 생산자의
confidence를 직접 비교하거나 중첩 탐지를 단순히 제거하면 보호할 구간을 잃을 수 있다.
기존 분류·가중식 ADR을 보완하여 현재 구현의 계약과 통합 제약을 기록한다.

## 결정

confidence 필드는 필수이며 0~1 또는 null을 허용한다. null을 0으로 대체하지 않는다.
tier는 deterministic, rule_anchored, model, candidate 중 하나를 명시해야 한다.
source 기본값은 unknown을 유지한다.

중첩 해소는 tier, 보호 분류, span 길이 순서로 우선순위를 정한다. 그 뒤 출처·타입의
고정 순서로 그룹을 정렬하며, 같은 source·타입·tier 그룹의 모든 confidence가
산정된 경우에만 confidence를 비교한다. source가 unknown 또는 빈 문자열이면 비교하지
않는다. 마지막 동률은 시작 좌표·normalized·직렬화 값으로 해소한다. 이 값들은
내부 비교용이며 감사 로그로 출력해서는 안 된다.

패배한 탐지의 전 구간을 같은 수준 이상의 보호 분류로 덮을 수 없으면 fail-closed한다.
async L5 경계는 고정 오류 코드로 실패를 반환하고 입력 탐지 목록을 보존한다.
오케스트레이터는 실패한 요청에서 L6/L7을 호출하지 않아야 한다.

민감정보 confidence가 null이면 정책 대체 점수 80과 TOKENIZE를 적용한다. 실제 0은
0점과 TOKENIZE를 유지한다. 직접·서비스 식별자와 지역 QI는 기존 점수 규칙을 유지한다.
실험 가중식은 null confidence를 거부하며 운영 점수와 분리한다.

## 검토한 대안

- null을 0으로 변환: 미산정을 낮은 위험이라는 증거로 오인하므로 제외했다.
- tier를 MODEL로 기본 설정: 생산자가 제공하지 않은 근거를 추정하므로 제외했다.
- 모든 생산자의 confidence 직접 비교: 산정 척도가 같다는 보장이 없어 제외했다.
- 부분 중첩 span을 임의 병합·절단: 엔터티 유형과 보호 구간을 바꿀 수 있어 제외했다.

## 결과

미산정과 0점을 구분하고 입력 순서에 독립적인 중첩 해소를 제공한다. 부분 중첩 요청이
실패할 수 있으며 L3/L4 생산자는 tier를 명시하도록 함께 이행해야 한다.

2026-09-26에 확인한 develop(e50a982)의 schemas.py와 add/add 충돌이 있다.
해당 develop의 mock L3/L4는 tier를 생략한다. 따라서 한쪽 스키마를 단순 선택하는
충돌 해결만으로 통합 완료를 선언할 수 없다. 생산자 호환성과 L5 실패 시 L6/L7 미호출을
통합 테스트로 검증해야 한다.

L5 경계의 고정 오류 코드만으로 전체 로깅 안전성이 보장되지는 않는다. 공통 컨텍스트의
탐지 원문·vault_mapping 직렬화, develop 감사 로거의 출력, 입력값을 포함하는 직접 호출
예외는 별도 수정과 회귀 검증이 필요하다. 이 ADR은 해당 문제의 해결 또는 팀 승인을
선언하지 않는다.
