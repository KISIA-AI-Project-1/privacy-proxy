# 0004. sensitive/ 재설계: 사전·프레임 규칙 기반, 2번/3번 분리

상태: Accepted
날짜: 2026-10-05
관련 레이어: L4

## 배경
이전 `sensitive/`(가족·종교·재정·건강, KoELECTRA 재판정)는 PIPA 23조 검토 후 폐기·제거했음(`29ab07a`).
이번은 같은 이름의 재설계이고 범위는 건강 + 성생활만. 입력은 LLM 프롬프트 자유텍스트.

## 결정
- 모델 학습 없이 사전 + 서술 프레임 규칙으로만 탐지함. 의약품 브랜드·성분 사전은 만들지 않음.
- 탐지를 둘로 나눔. **2번(본인 상태 진술)** 만 이번에 구현, **3번(구매 패턴·반복 단서)** 은 다음 단계.
- 2번: 질병·상태어 + 서술 프레임이 같은 문장에 있을 때만 방출함. 용어 단독은 방출 안 함.
  구매 프레임은 버림(3번 몫). 광고 문구("~에 좋은")는 복용 프레임이 같이 있을 때만 양성.
- 공백 제거 문장에서 매칭하고 원문 좌표로 역매핑함. 문장 분리는 정규식(`.!?。\n`), 소수점·말줄임표는 경계 아님.
- 엔진(`engine.py`)은 카테고리 공용 한 벌. 카테고리 폴더는 `lexicon.yaml` + `guards.py`만 가짐.
- 같은 span이 건강·성생활 양쪽에 걸리면 `SENSITIVE_HEALTH`로 합침.
- 1인칭 판별은 하지 않음. 3인칭 서술("엄마가 당뇨 있어요")도 방출함. 제3자 건강정보도 민감정보라 L4에서 거르지 않고 L5 판정에 맡김.
- 출력: `tier=RULE_ANCHORED`, `source=L4_SENSITIVE_<TYPE>`, confidence는 `recognizers/context.py`의 `score` 재사용.
  `DetectedPII` 필드 추가 없음. 위험도 판정은 L5 소관이라 L4에 judge 함수 없음.

## 한계
- 되묻는 문장("당뇨 있어요?")은 `?`로 끊길 뿐 의문 여부는 안 봄.
- "우울해서 약 먹어요"처럼 사전어 변형은 못 잡음(사전에 있는 표기만).
- 마침표 앞이 숫자면 경계로 안 봄.
