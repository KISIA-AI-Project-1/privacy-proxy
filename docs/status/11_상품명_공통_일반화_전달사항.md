# 상품명 공통 일반화: L5 변경 및 L4·L6 수정 요청

기준일: 2026-10-19 (KST)
기준 develop: `ea483abe6a2f9f4777fb2348c54fc06879112bf7`.

## 담당 범위와 현재 상태

팀원3은 L5 담당이다. 이번 변경은 L5 정책 설명과 L5 단위 테스트, 전달 문서에 한정한다.
L4 탐지기, L6 토크나이저, L8 복원기, 공통 스키마 및 통합/E2E 테스트는 수정하지 않는다.
앞서 로컬에서 작성했던 L6 코드·관련 테스트 수정은 원복했으며 해당 구현 패치는 폐기했다.

현재 develop에서 L5는 이미 PRODUCT_ITEM을 점수와 무관하게 GENERALIZE로 판단한다.
이번 L5 변경은 설명을 `상품명 보호: '상품'으로 비가역 일반화 요청(복원 제외)`로 명확히 한다.
정책 설명은 후속 단계에 대한 요청이며, L6 구현·실제 일반화 완료를 의미하지 않는다.
점수·임계값·QI 분류·정기배송 유지 정책은 변경하지 않는다.
L5는 원문을 직접 수정하거나 Vault 매핑을 생성하지 않는다.

## L4 담당자에게 전달

상품명 공통 일반화 방식을 사용하기로 결정했습니다. 기존 상품명 탐지는 유지하고,
탐지된 원문 span을 PRODUCT_ITEM으로 전달해주세요. PURCHASE_PATTERN도 기존 계약대로
전달하면 됩니다. 이번 결정에 따른 L4 코드 변경이나 상품 범주 필드 추가는 필요하지 않습니다.
생활용품·의약품 등의 범주를 추론하거나, 상품 구매로 건강·성생활 상태를 추론하지 않습니다.
실제 민감정보 진술은 기존 민감정보 타입으로 전달합니다. 상품명 미탐 여부는 별도 점검 대상입니다.

## L6 담당자에게 수정 요청

L5가 PRODUCT_ITEM에 GENERALIZE를 요청하면 공통 표현 **상품**으로 비가역 치환해주세요.
현재 develop의 PRODUCT_ITEM + GENERALIZE는 가역 PRODUCT 토큰으로 처리되어
L5 판단과 L6 실제 결과가 다릅니다. 아래는 아직 L6 담당자가 반영해야 할 요청입니다.

1. `POLICY_SPECS["PRODUCT_ITEM"]["GENERALIZE"]`를 가역 토큰 대신 상품 공통 일반화 함수로 연결.
2. 일반화 함수는 상품명과 무관하게 `상품`을 반환. 상품 범주·민감 상태는 추론하지 않음.
3. 이 일반화 처리에 상품 Vault 매핑·token_types를 만들지 않고, 실제 action은 GENERALIZE로 기록.
4. 요청 전체가 TOKENIZE여도 항목별 GENERALIZE를 우선 적용.
5. 상품명 뒤 조사가 어색해지지 않도록 처리 검토. 예: `임신테스트기를` → `상품을`.
6. PURCHASE_PATTERN은 기존대로 원문 유지. 다른 식별자의 치환·복원 정책은 유지.
7. 명시적 상품 TOKENIZE·ALLOW의 기존 계약은 유지. 정상 L5는 상품에 GENERALIZE를 전달함.
8. 기존 세션 상품 매핑을 새 GENERALIZE 요청의 복원 매핑으로 재사용하지 않음.

L6 반영 후 확인할 항목:

- 입력 `매달 임신테스트기를 주문해요.` → 외부 전송 `매달 상품을 주문해요.`
- 에코 응답 복원 후에도 상품명이 되살아나지 않음.
- 전화번호 혼합 요청에서는 상품 일반화·전화번호 토큰화/복원이 함께 동작.
- 계획/실제 action이 모두 GENERALIZE이며 상품 Vault 매핑이 없음.
- 낮은 QI 점수·높은 QI 점수·요청 전체 TOKENIZE·기존 세션 매핑에서 같은 계약 유지.

L6 담당자가 Vault 단위 테스트, 항목별 정책 통합 테스트와 상품 E2E 기대값을 함께 갱신해주세요.
L5에서는 실제 L6 적용 완료 여부를 대신 표시하지 않습니다.

## 일반화의 한계

상품별 사용법·성분·호환성 상담에 필요한 구체적 정보는 사라집니다.
배송·교환·정기배송 맥락 중심의 처리에 맞춘 결정입니다.
범주별 일반화는 별도 분류 기준과 L4 출력 계약을 마련한 뒤 검토합니다.
탐지된 상품명 span에만 적용하며 L4가 놓친 상품명을 보호하는 기능은 아닙니다.

## 검증 범위

이번 변경은 L5 단위 정책·위험평가·L5 경계 회귀 및 린트·타입 검사로 확인합니다.
앞서 L6 수정본으로 실행한 334개 테스트 결과는 원복한 구현의 결과이므로
현재 L6 구현 완료 근거로 사용할 수 없습니다. L6 변경·실연동 검증은 담당자 반영 후 필요합니다.
