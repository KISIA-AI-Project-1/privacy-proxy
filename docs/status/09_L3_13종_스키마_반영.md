# L3 13종 스키마 반영 (2026-09-27)

첨부 schemas-2.py의 필드 계약과 검증 오류 입력 숨김을 반영하고,
사용자가 확인한 L3 확정 13종을 추가했다.
목록에서 붙여 쓴 EMAIL_ADDRESSAGE는 EMAIL_ADDRESS와 AGE로 구분했다.
첨부 enum 자체는 기존 19종이므로 파일 교체만으로는 부족하다.

| 분류 | L3 타입 | 운영 처리 |
| --- | --- | --- |
| 직접식별자 | PERSON_EN, ADDRESS, KR_RRN, PHONE_NUMBER, EMAIL_ADDRESS, KR_PASSPORT, KR_FRN, KR_DRIVER_LICENSE | TOKENIZE, 최소 80점 |
| 서비스 식별자 | KR_BRN | TOKENIZE, 최소 85점 |
| 지역 QI | LOCATION | LOCATION_INFORMAL과 동일한 상세도별 5/15/22점 |
| 연령 QI | AGE, AGE_GROUP, DATE_OF_BIRTH | 각각 20/8/22점 |

연령·연령대·생년월일은 동일 차원의 대표값 중 가장 구체적인 항목만 합산한다.
LOCATION과 LOCATION_INFORMAL의 동일 지역 문자열도 중복 합산하지 않는다.
연령·지역 결합은 기존 결합 보너스와 GENERALIZE 임계값을 따른다.
새 연령/생년월일 점수 및 실험용 weighted_score 가중치는 초기 정책값이며,
실제 데이터 보정이나 팀 승인 완료를 의미하지 않는다.

이전 이름 PHONE, EMAIL, RRN, BUSINESS_REGISTRATION_NUMBER는 제거했다.
각각 PHONE_NUMBER, EMAIL_ADDRESS, KR_RRN, KR_BRN만 사용한다.
구버전 이름은 자동 변환하지 않고 알 수 없는 타입으로 거부한다.
현재 L5 지원 엔터티는 L3 13 + L4 14 = 27종이다.
ETC와 이전 이름 4개를 enum에서 제거했다. 스키마와 L5 지원 목록은 동일한 27종이다.
DetectedPII의 문자열 수신 계약은 유지하되 ETC·미등록 문자열은 L5에서 실패 처리한다.
비동기 실행 경계에서는 L5_VALIDATION_FAILED로 기록되어 다음 단계 진행을 막는다.
별도 검토 큐는 구현하지 않았으며, 미등록 타입을 정상 정보로 통과시키지 않는다.
기존 문서의 19종/18종 및 L3 미지원 설명은 과거 현황이다.
알 수 없는 이름과 대소문자·공백 변형은 계속 실패 처리한다.
confidence는 명시적 null을 허용하고 tier는 필수다.

실제 L3 탐지기는 이 저장소에 없으므로 이번 변경은 스키마와 L5 수신 처리 범위다.
원격 통합으로 추가된 mock L3의 전화번호 타입도 PHONE_NUMBER로 맞췄다.
실제 생산자 연결은 미검증이다. 13종 각각의 비동기 L5 실행, 분류·가중치 누락,
QI 중복과 결합, 기존 계약 호환성에 대한 회귀 테스트를 추가했다.
