## 2. DetectionTier

| enum | JSON 값 |
|---|---|
| `DETERMINISTIC` | `deterministic` |
| `RULE_ANCHORED` | `rule_anchored` |
| `MODEL` | `model` |
| `CANDIDATE` | `candidate` |

우선순위는 `DETERMINISTIC > RULE_ANCHORED > MODEL > CANDIDATE`다.

## 3. DetectedPII 계약

| 필드 | 규칙 |
|---|---|
| `entity_type` | `EntityType | str`; L5는 표준 18종만 평가 |
| `original_value` | 원문 span 값 |
| `start_idx` | 전역 원문 기준 0-based inclusive |
| `end_idx` | 전역 원문 기준 0-based exclusive |
| `confidence` | 필드 필수, 0.0~1.0 또는 null (미산정) |
| `segment_id` | 기본값 `seg-1` |
| `normalized` | 기본값 빈 문자열 |
| `tier` | 필수, null 및 생략 불가 |
| `source` | 기본값 `unknown` |

L5 진입 시 다음 불변식을 검증한다.

```python
raw_prompt[start_idx:end_idx] == original_value
```

## 4. 구현된 안전 규칙

- `EntityType`을 공통 엔터티 이름의 단일 기준으로 사용
- L5 지원 18종 외 타입과 `ETC`를 fail-closed 처리
- 타입명 자동 별칭 변환이나 대소문자 보정 없음
- allowlist 검증을 overlap resolver보다 먼저 실행
- `ACCOUNT_NUMBER`를 L5 `DIRECT_IDENTIFIER`로 처리
- L4 PS/LC 변환과 segment-local → 전역 offset 변환 구현
- 중첩 시 tier, 보호 분류, span 길이 순서로 winner 결정. 같은 출처·타입·tier의 모든 confidence가 숫자인 경우에만 비교
- 중첩 해소로 보호 구간이 유실되거나 보호 분류가 낮아지면 fail-closed
- 오류 메시지에 원문 탐지값을 포함하지 않음
