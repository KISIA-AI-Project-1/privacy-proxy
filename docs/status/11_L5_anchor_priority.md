# L5 앵커 연결과 면허 충돌 예외

최종 문서 정리: 2026-10-22. 현재 상태는 [인수인계](../HANDOFF_팀원3_L5.md), 설계 결정은 [ADR 0005](../decisions/0005-l5-anchor-priority-and-explicit-ties.md)를 참고한다.

2026-10-21. PR #57이 머지된 develop 93fd640 기준으로 로컬 브랜치를 fast-forward 통합했다.
L4 앵커 전달 9837cdf와 계좌번호 전달 37157d7을 포함한다. 기존 L5 미커밋 변경은 유지했다.

L5는 전달받은 anchor_text/start/end가 전체 raw_prompt의 실제 구간과 일치하는지 확인하고 값과 앵커 사이 문자열을 검사한다. 앞쪽은 가로 공백·조사(은/는/이/가/의)·콜론(전각 포함)/등호, 뒤쪽은 가로 공백·조사(은/는/이/가)를 허용하며 최대 6자로 제한한다. 줄바꿈, 문장부호, 설명 단어, 중간 숫자는 직접 연결이 아니다. 이는 의미 분석이 아닌 보수적인 연결 규칙이다.

동일 segment_id 및 동일 값 구간에서 직접 연결된 L4 RULE_ANCHORED 주문/송장/고객/계좌번호가 면허 후보와 충돌하면, 면허 해석과 직접 연결 근거가 없는 동급 이하 번호 해석을 제외한다. 예외를 발생시킨 직접 연결 후보를 남겨서 다른 간접 번호 후보가 대신 승리하지 못하게 한다. 면허 이외의 deterministic 후보 우선순위, 생산자 tier 및 confidence는 바꾸지 않는다. confidence 비교로 예외를 판단하지 않는다. 부분 겹침에는 예외를 적용하지 않으며 기존 보호 구간 누락 검증을 유지한다.

원문 또는 앵커 근거가 없거나 일치하지 않으면 기존 tier 우선순위를 유지한다. L4의 가장 가까운 앵커 선택을 L5에서 다시 수행하지 않는다. 양성/음성 연결, 입력 순서, 세그먼트 분리, 다른 deterministic 후보, 전역 오프셋 및 L4→L5 항목 TOKENIZE를 회귀 검증한다.


## 동률 처리 수정

전체 model_dump_json 비교를 제거했다. 기존 tier·보호 분류·길이·타입·출처 순서를 유지하고, 동일 그룹에서는 원문으로 검증한 직접 연결 여부를 confidence보다 먼저 비교한다. 이후 비교 가능한 confidence, 시작 좌표, normalized, original_value, anchor_text/start/end를 명시적으로 사용한다. 마지막 앵커 필드 순서는 안정적인 대표 선택용이며 의미상 우선순위를 뜻하지 않는다.

출처가 unknown/빈 문자열이거나 같은 그룹에 confidence=None이 있으면 점수 크기를 비교하지 않는다. 명시적인 키가 완전히 같은 동일 세그먼트 후보들의 confidence가 다르면 ValueError로 실패한다. L5 경계에서는 L5_VALIDATION_FAILED로 전환하고 입력을 보존한다. 이미 다른 강한 후보에 가려진 중복은 실패를 유발하지 않는다. 완전히 같은 중복은 하나만 남기며 서로 다른 세그먼트의 점수는 섞지 않는다. 생산자의 confidence를 새로 만들거나 None으로 덮어쓰지 않는다.

기존 nullable 테스트의 동일 조건/다른 confidence 사례는 JSON 순서로 임의 선택하던 기대값을 모든 순서에서 실패하는 기대값으로 변경했다. 이 동작은 불명확한 중복을 해결하는 합의 전의 보수적 처리이며, 해당 입력은 요청 실패가 된다는 운영 영향이 있다.

## L4 담당자 확인 요청안 — 아래는 머지 전 작성 기록

- 전달은 anchor_text, anchor_start, anchor_end의 세 필드이며, 없으면 모두 None인가? 문자열은 정규화 이전 원문 조각인가?
- L4 로컬 좌표는 adapter에서 값과 앵커 모두 offset_base를 정확히 한 번 더해 전체 raw_prompt 좌표로 바꾸는가? segment_id의 경계를 넘는 앵커를 전달하지 않는가?
- 같은 값 주변에서 가장 가까운 앵커 하나를 선택하고 거리 동률은 앞쪽, 긴 앵커 순으로 고르는 계약을 유지하는가? L5는 앵커를 다시 검색하지 않는다.
- 동일 값의 여러 타입/동일 타입 중복을 내보낼 수 있는가? 같은 source·type·tier 및 동일 근거인데 confidence가 다를 수 있는가? 중복 점수 병합은 L5에서 아직 하지 않는다.
- L5 직접 연결 규칙(앞/뒤 허용 조사·구분자, 최대 6자, 줄바꿈 불허)과 예외 대상 4종을 함께 확인한다. 이 기준은 L5 초안이며 L4 구현 완료 통보와 별개로 합의가 필요하다.

아래 머지 후 확인과 E2E 결과가 이 대기 상태를 갱신한다. 필드·좌표·선택 방식은 코드로 확인했으며, 남은 정책 확인 사항은 최신 인수인계를 따른다.


## 머지 후 코드 확인

- 공통 필드는 anchor_text/start/end이며 모든 값이 함께 채워지거나 None인 스키마 계약을 확인했다.
- L4 find_anchor는 원문 앵커와 로컬 반개구간 좌표를 반환하며, 거리 동률 시 앞쪽·긴 앵커를 선택한다.
- adapter가 값과 앵커 좌표 모두에 offset_base를 더하는 것을 확인했다.
- 최종 머지에는 ACCOUNT_NUMBER의 2그룹·3그룹 경로 모두 앵커 전달이 포함됐다.
- 실제 네 종류 L4 인식기 → 전역 좌표 adapter → L5를 검증했다. 면허 충돌 입력은 resolver 검증용 합성 후보이며 모든 번호 형식에 실제 L3 면허 탐지가 발생한다는 뜻이 아니다.
- 관련 단위·통합·파이프라인 테스트 266개 통과. 이 중 파이프라인 테스트는 L3/외부 LLM 스텁을 포함하므로 전체 모델 기반 E2E와 구분한다.

이 확인은 머지 코드의 동작 검증이며 L4 담당자와의 별도 정책 합의를 대신하지 않는다. 최대 6자 연결 기준 및 모호한 confidence 중복의 실패 처리 기준은 L5 정책으로 명시했다.
