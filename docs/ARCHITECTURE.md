# 아키텍처

파이프라인 다이어그램과 레이어별 담당은 [README](../README.md)에 있다.
이 문서는 레이어 사이의 **계약**, 즉 서로 무엇을 주고받는지를 정한다.
구현이 진행되면서 각 담당자가 자기 절을 채운다.

## 신뢰 경계

```
직원 PC ──▶ [ L1 … L6 ]  ──▶  L7  ──▶ 외부 LLM
                 ▲                        │
             원문 PII 존재                 │ 토큰만
                 │                        ▼
            [ L9 ◀── L8 ] ◀───────────────┘
```

원문 PII가 메모리에 존재하는 구간은 **L1~L6, L8~L9**뿐이다.
L7이 만드는 아웃바운드 페이로드에는 토큰만 남는다. 이 불변식이 깨지면
프로젝트의 전제(Zero exposure)가 무너지므로, L7 통과 직전에 검증 훅을 둔다.

## 레이어 간 계약

각 레이어는 앞 레이어의 출력만 입력으로 받는다. 전역 상태를 공유하지 않는다.

| 경계 | 넘겨주는 것 | 정하는 사람 |
| --- | --- | --- |
| L2 → L3 | 원문 텍스트 + 원본 JSON path (치환 후 되돌려 꽂을 위치) | 공통 |
| L3 → L4 | 탐지 결과 목록 (entity_type, start, end, score) | 정민우 → 이선학 |
| L4 → L5 | L3 결과에 이커머스 엔티티를 병합한 목록 | 이선학 → 형지원 |
| L5 → L6 | 최종 탐지 목록 + Risk Score(R) + 등급별 처리 정책 | 형지원 → 윤채림 |
| L6 → L7 | 토큰으로 치환된 페이로드 + 세션 ID | 윤채림 → 김민석 |
| L8 → 클라이언트 | 역치환된 응답 (role 기반 선택 복원 적용) | 김민석 |

탐지 결과의 공통 표현은 Presidio `RecognizerResult`(entity_type, start, end, score)를
따른다. L4의 커스텀 엔티티도 같은 형태로 낸다. 오프셋은 **L2가 넘긴 원문 문자열
기준**이며, 조사 분리(L4)로 경계가 바뀌면 그 시점에 오프셋을 갱신해 넘긴다.

## 미결정 사항

아래는 아직 정하지 않았다. 정해지는 대로 `docs/decisions/`에 ADR로 남긴다.

- 탐지 결과가 겹칠 때(L3와 L4가 같은 구간을 다르게 분류) 우선순위 규칙
- Risk Score 등급별 정책 — 차단인지, 강한 치환인지, 경고 후 통과인지
- 세션 ID의 수명과 범위 — 요청 단위인지 대화 단위인지
- 스트리밍 응답에서 토큰이 청크 경계에 걸릴 때 버퍼 최대 보류 길이
- 역치환 실패 시 동작 — 토큰을 그대로 노출할지, 에러로 처리할지
